# Integration and responsibility

Construct `AuditEvent` and evidence values directly. Static digest/redaction helpers need no ConfigProvider. App explicitly binds `AuditRecorder`, `AuditArchiveStorage`, `AuditTrailExporter` and `AuditTrailVerifier`; records remain outside the container. Pass the host's `CanonicalEncoder` to each digest computation.

Audit metadata is a string-keyed root object containing only JSON scalars and nested arrays. `AuditMetadata` bounds nesting at 32 levels, total entries at 512 and encoded JSON at 65,536 bytes. Invalid UTF-8, nonfinite numbers, resources, recursive arrays and all objects are refused with `InvalidArgumentException`; user serialization callbacks never run. Snapshots detach nested references. `metadataAsJson()` preserves App's JSON_FORCE_OBJECT projection, including nested lists; canonical digests instead consume the decoded metadata array through the explicit encoder.

The host must select safe context before recording; the constructor does not infer what every business secret is. Apply `AuditMetadataRedactor::redact()` at the archive boundary. Separator-insensitive credential keys and opaque strings longer than 128 bytes are replaced by `[redacted]`. The counter changes only after the whole bounded snapshot succeeds. Redaction never mutates the original event, its references or stored digests. Encrypted/callback-bearing object values are refused rather than serialized; arbitrary string ciphertext should be classified as secret by host metadata policy.

Event SHA-256 binds exact fields under `kumwe-audit-event-v1` and stored `Y-m-d H:i:s` timestamp strings. Anchor SHA-256 uses `kumwe-audit-anchor-v1`; rolling digests include ordered `position:digest` lines. GenericV1 bytes and the exact deployed corpus/version are part of evidence. No alternate canonical profile or encoder fallback is selected. Rolling mutation, reordering, deletion and position gaps change the digest; sequence allocation, interpreting findings and trusting anchors remain host verification responsibilities.

`AuditVerificationReport::intact()` describes evidence only. `guarded()` also requires observed `AuditEnforcementState::Active`; package code never installs or observes database guards. `StoredAuditArchive`, export manifests and findings carry host facts without authorizing archive access or retention. Their constructors preserve the documented projections rather than proving external storage events occurred.

The executable consumer implements recorder/storage ports with in-memory host adapters, performs secret redaction and validates archive evidence. Database atomicity, privileged exports, key custody, retention/deletion, restore, incident response and operational verification jobs remain App responsibilities. No filesystem writer or production verifier is shipped.
